# 大论文 skill

本文件用于本科毕业论文、研究生学位论文、工程标书、长篇课程论文、技术报告、申报书和其他篇幅较大的文章起稿、润色、格式统一、图片插入保护和终稿自检。默认不涉及任何具体工程细节，只沉淀通用写作和文档处理方法。

## 1. 适用场景

当用户提出以下需求时，优先使用本文件：

- “大论文 skill”“大论文起稿”“毕业论文快速成稿”“硕士论文/博士论文改稿”。
- “工程标书”“投标文件”“第几章软件设计/硬件设计”“长篇报告统一格式”。
- “统一第一章/第二章格式”“标题序号乱了”“目录不更新”“图表编号断了”。
- “Word 里图片插入后消失”“图片被覆盖”“重新生成文档后图片没了”“WPS 图片位置跑了”。
- “生成风格迁移提示词”“优化 GPT 提示词”“按目标模板重排格式”“做终稿自检”。
- “评估脚本/方案/材料是否值得写专利、软著、论文或标书章节”。
- “确认需要哪些资料、手册、模板、图片、表格或原始材料”。
- “详细解读这张图”“先给 GPT 讲懂再给 GPT 提示词”“优化绘图提示词”。

## 2. 适用对象

本文件面向“篇幅大、结构多、图片表格多、格式要求强、需要反复修改”的文档任务。

### 2.1 使用人群

- 本科生：毕业论文、课程设计报告、创新创业项目书、竞赛技术报告。
- 研究生：硕士论文、博士论文、开题报告、中期检查、学位论文预答辩材料、投稿论文扩展稿。
- 工程技术人员：技术方案、项目报告、测试报告、验收材料、实施方案、工程标书。
- 教师或导师助手：论文模板整理、章节审阅、格式检查、图表规范化、学生初稿批改。
- 科研团队或项目组：长文档协作、资料汇编、标书章节统一、成果材料整理。

### 2.2 文档类型

- 学位类：本科毕业论文、硕士论文、博士论文、开题报告、中期报告、答辩稿文字底稿。
- 论文类：中文核心论文初稿、期刊论文扩展版、会议论文扩展版、综述稿。
- 工程类：工程标书、技术规格书、需求分析报告、总体设计报告、测试与验收报告。
- 项目类：申报书、结题报告、阶段总结、可行性研究报告、成果鉴定材料。
- 图文类：含大量图片、表格、公式、题注、目录和交叉引用的 Word/WPS 文档。

### 2.3 任务类型

- 从零起稿：搭目录、建章节骨架、生成第一版粗稿。
- 结构重搭：调整章节目次、统一章标题语法、补章节功能说明。
- 格式治理：统一 Word/WPS 样式、标题编号、图题表题、目录和页码。
- 图片保护：插图、替换图、红框标注、图片清单、图片不消失不被覆盖。
- 提示词生成：风格迁移、读图讲解、绘图提示词、GPT 修改提示词。
- 终稿自检：检查事实、证据、图表、公式、引用、格式、目录和导出 PDF。
- 成果判断：判断脚本、流程、方案、图件或章节适合写成专利、软著、论文亮点还是标书亮点。

### 2.4 不适用或需谨慎的对象

- 纯粹文学创作、广告文案、短社媒文案，不优先使用本文件。
- 法律、医学、财务等高风险正式结论，必须提醒用户找专业人员确认。
- 缺少原始材料却要求生成确定实验结果、真实引用、验收结论或专利授权概率时，只能给保守框架，不能编造。
- 已经定稿且含大量图片、公式、域代码的 Word/WPS 文档，不应直接整文覆盖式改写，应先备份并执行图片和对象保护检查。

## 3. 总原则

大篇幅文档先保结构，再保证据，再保格式，最后润色语言。

1. 不编造实验、数据、引用、章节来源、验收指标或导师要求。
2. 不把图片、题注、交叉引用和标题编号当成普通文本随意覆盖。
3. 不在已有图片和域代码的段落上使用整段替换，尤其不要用会清空 run、drawing、field 的粗暴替换方式。
4. 先建立章节骨架和样式映射，再批量填充正文；先统一样式，再插入最终图片；若图片已插入，后续格式脚本必须避开图片段落。
5. 每轮修改只解决一类问题：结构、证据、图片、编号、格式、语言，不要一轮里同时大改所有层面。

## 4. 快速起稿流程

长文档不要从摘要硬写，先做“目录级骨架”。

1. 定义文档类型：本科论文、硕士论文、博士论文、工程标书、课程论文、技术报告或申报书。
2. 建立标题层级：章、节、小节最多三级为主，必要时用条目列表补充，不滥用四级标题。
3. 给每一章写一句任务说明：本章回答什么问题、承接上一章什么内容、输出什么证据。
4. 为每一节建立四列表：本节目的、输入材料、预期图表、需要人工确认的证据。
5. 先生成“能站住的粗稿”：结构完整、术语统一、图表占位明确、引用口径可追踪。
6. 再做“六轮自改”：主线、证据、图表、格式、编号、语言。

常见大论文骨架：

- 第1章 绪论：背景、问题、意义、国内外研究现状、研究内容、技术路线。
- 第2章 理论基础或需求分析：概念、规范、系统边界、指标、约束。
- 第3章 方法或总体设计：总体框架、关键流程、模型、算法、模块关系。
- 第4章 实现或实验设计：实现环境、参数、流程、数据来源、测试方案。
- 第5章 结果与分析：结果展示、对比分析、误差或问题讨论。
- 第6章 总结与展望：主要工作、结论、局限和后续工作。

工程标书可按“需求理解、总体方案、技术路线、实施计划、质量控制、风险与保障、验收与交付”组织。

## 5. 标题序号和样式经验

标题编号必须依赖样式，不靠手打空格和手动加粗维持。

1. 先确定编号体系：论文常用“第1章、1.1、1.1.1”；期刊论文常用“1、1.1、1.1.1”；标书常用“章、节、条款”或招标文件指定编号。
2. 一级、二级、三级标题分别绑定稳定样式，正文、图题、表题、公式说明也分别绑定样式。
3. 不跳级：不能从一级标题直接跳到三级标题。
4. 同一层标题语法保持一致，例如都用“对象 + 方法/设计/分析/验证”的结构。
5. 修改标题文字时只改标题内容，不删除标题段落的样式和编号域。
6. 改完标题后必须更新目录，并检查目录文字、页码和正文标题完全一致。

标题自检：

- 是否存在重复章号、断号、跳号。
- 是否存在手动输入的伪编号。
- 是否存在标题像口号、像任务清单或像软件菜单。
- 目录中是否出现正文段落、图题或表题。
- 同级标题长度和语法是否明显不一致。

## 6. 图片不消失、不被覆盖的 Word/WPS 经验

图片丢失通常不是图片真的“消失”，而是文档关系、段落 run、浮动锚点或媒体文件被覆盖。处理大文档时按以下规则做。

### 5.1 插图前

1. 不直接依赖剪贴板和临时路径图片。先把图片保存到稳定目录，如 `assets/figures` 或 `figures`。
2. 文件名使用稳定命名，如 `fig_2_1_system.png`、`fig_3_2_flow.svg`，不要长期使用 `image1.png`、`截图.png`、`新建图片.png`。
3. 建立图片清单：图号、文件名、插入章节、题注、来源、是否终稿图、是否需要人工确认。
4. 优先使用清晰的 PNG/PDF/SVG 源图；截图只作为临时占位时，必须标记为“待替换”。

### 5.2 插图时

1. 学位论文和标书中，正文图优先使用“嵌入型/与文字在一行”或稳定段落锚定，减少浮动图乱跑。
2. 每张图单独成段，图题单独成段，图前后不要夹杂空白文本框。
3. 图题用自动题注或统一样式，不手工反复复制“图 1-1”。
4. 宽图、流程图和多面板图先统一宽度，再插入；不要插入后靠拖拽反复缩放。
5. 红框标注图只用于审稿或沟通副本，保留原图，另存 `*_marked`，不要覆盖原始图片。

### 5.3 自动化修改时

若用脚本或批量工具处理 `.docx`：

1. 不要对含图片、公式、域代码、交叉引用的段落执行整段 `paragraph.text = ...` 式替换；这会清空 runs、图片 drawing、域代码和超链接。
2. 不要把整个文档重新生成一遍再覆盖原文件，除非图片、题注、关系文件和样式都由同一流程完整重建。
3. 只修改目标段落或目标样式。遇到含 `<w:drawing>`、图片关系、公式对象、域代码的段落，默认跳过或仅调整段落样式。
4. 若必须替换文字，优先做 run 级别替换，并保持原 run 的图片和域结构。
5. 保存前后检查 `.docx` 内部 `word/media/*` 数量、图片关系数量、正文中的图片对象数量是否减少。
6. 对已有终稿图片的文档，先改样式和标题，最后插图；若图片已经插好，后续脚本只做非破坏性格式修正。

### 5.4 插图后自检

每次保存后至少检查：

- 图片总数是否和清单一致。
- 每张图是否仍在目标章节附近。
- 图题是否紧跟图片，且图号连续。
- 目录、图目录、表目录是否能更新。
- 导出 PDF 后图片是否显示完整、没有被文字遮挡、没有跑到页边。
- 打开关闭一次文档后图片是否仍存在。

## 7. 格式迁移经验

格式迁移不是简单“套模板”，而是把旧文档内容映射到新文档样式体系。

1. 先提取目标模板规则：页面、字体、行距、标题、正文、图题、表题、表格、公式、参考文献。
2. 建立样式映射表：旧样式或旧格式 -> 新样式。
3. 优先迁移文本结构和样式，不直接复制目标模板的全部内容。
4. 对图片、公式、表格、参考文献分别设保护规则，不和普通正文一起批量处理。
5. 迁移后先检查结构和图片，再检查细节格式。

格式迁移提示词：

```text
请把以下文档内容迁移为目标模板风格。要求：
1. 保留事实、数据、引用编号、图表编号、公式编号和术语，不新增未经提供的信息。
2. 先输出样式映射表：标题、正文、图题、表题、表格、公式、参考文献分别如何处理。
3. 对含图片、公式、交叉引用的段落只给修改建议，不做会破坏对象关系的整段替换。
4. 输出“结构问题、格式问题、图片/题注问题、需人工确认问题”四类清单。
5. 最后给出可执行的分轮修改顺序。
```

## 8. 红框标注和审稿沟通图

红框标注用于说明问题，不等于终稿图。

1. 保留原图，复制一份做标注。
2. 红框只圈核心问题，不把整张图涂满。
3. 标注文字短、准、少，优先使用编号加说明表。
4. 标注图文件名加 `_marked` 或 `_review`。
5. 插入论文或标书终稿前，确认是否应替换回无标注原图。

红框标注提示词：

```text
请基于这张图生成审稿沟通用红框标注版本。要求：
1. 不改变原图核心内容和比例。
2. 只用红框圈出需要修改或核查的位置。
3. 每个红框旁添加简短编号，如 A、B、C。
4. 另附编号说明表，说明问题和建议，不把长句直接堆在图上。
5. 输出标注版文件，同时保留原图文件。
```

## 9. 大文档终稿自检清单

终稿自检按“会阻塞提交的问题”优先。

### 9.1 阻塞项

- 文档类型、学校/期刊/招标方模板是否匹配。
- 目录、页码、标题编号是否更新。
- 图片是否齐全，图题是否连续，图文是否对应。
- 表格是否齐全，表题是否连续，跨页表头是否处理。
- 公式编号是否连续，变量是否解释。
- 参考文献是否真实、可查、格式统一，正文引用是否一一对应。
- 数据来源、实验来源、案例来源是否可解释。
- 是否存在“见下图”“如下表”但实际图表缺失的情况。

### 9.2 质量项

- 摘要是否有对象、方法、结果、结论。
- 绪论是否说明问题来源，而不是泛泛介绍背景。
- 每章开头是否说明本章任务，结尾是否有小结。
- 图表是否承担证据功能，而不是装饰。
- 段落是否过长，是否存在一页只有一个巨段。
- 术语、缩写、单位、标点、数字格式是否统一。
- 语言是否像正式论文或标书，而不是聊天记录、项目流水账或宣传稿。

### 9.3 Word/WPS 技术项

- 更新目录、图目录、表目录后编号是否仍正确。
- 导出 PDF 后图片、公式、页眉页脚是否正常。
- 打开 PDF 检查前 10 页、中间随机 5 页、最后 5 页。
- 保存、关闭、重新打开后图片是否仍在。
- 另存副本后检查图片数量是否变化。

## 10. 输出模板

处理大论文或标书时，默认先输出下面四块，不急着直接大段润色：

1. 当前判断：文档处于起稿、结构成型、格式治理、图片修复、终稿自检中的哪一阶段。
2. 风险清单：图片、标题编号、目录、图表题注、证据口径、引用格式的风险。
3. 修改顺序：先结构，后图片，再编号，再目录，最后语言。
4. 交付物：章节骨架、样式映射表、图片清单、格式自检表、可直接替换的修订段落。

## 11. 长文档提示词模板

快速起稿：

```text
请按“大篇幅论文/报告快速起稿”方式处理以下材料。要求：
1. 不编造事实、数据、文献和结论。
2. 先给目录级骨架，明确章、节、小节标题。
3. 每节写清目的、应放材料、建议图表和需要人工确认的证据。
4. 再给第一轮可用粗稿，不追求华丽语言，优先保证结构闭环。
5. 最后给自检清单：标题编号、图片、表格、公式、引用、目录。
```

格式和编号自检：

```text
请只检查格式和编号，不改写正文内容。重点检查：
1. 章、节、小节标题是否连续、是否跳级、是否手工编号。
2. 目录是否应更新，目录项是否混入正文或图题。
3. 图题、表题、公式编号是否连续且与正文引用一致。
4. 图片是否可能因浮动锚点、临时路径或批量替换而丢失。
5. 输出问题表：位置、问题、风险等级、建议修复方式。
```

图片保护：

```text
请检查这个 Word/WPS 文档的图片保护风险。要求：
1. 不覆盖原文件。
2. 统计图片数量、图题数量和图片文件关系。
3. 标出可能被整段替换、样式迁移或重新生成文档破坏的图片段落。
4. 给出安全修改顺序。
5. 修改后再次检查图片数量、题注编号、目录和 PDF 导出效果。
```

## 12. 归档任务经验沉淀

以下经验来自多类已处理任务的通用抽象，不绑定任何具体工程项目。后续遇到相似任务时，按“场景 -> 判断 -> 输出物 -> 自检”的方式执行。

| 归档场景 | 经验抽象 | 推荐输出 |
| --- | --- | --- |
| 评估脚本、方案或材料是否值得写专利 | 不评价“文件名值不值钱”，先区分工具代码、技术方案、保护客体和证据链；软件类成果要落到技术问题、技术手段和技术效果，不把普通脚本包装成空泛专利 | 价值等级、可写方向、不建议方向、风险点、需补证据、建议标题 |
| 规范 Word/WPS 论文格式 | 格式不是纯外观，标题样式、题注、目录、交叉引用和图片关系是同一套结构；先做样式映射，再做批量修正 | 样式映射表、格式问题清单、安全修改顺序、终稿自检表 |
| 生成红框标注提示词 | 红框图是沟通副本，不是终稿图；保留原图，标注图另存，红框少而准，长说明放图外 | 原图保护规则、标注版命名、红框编号说明表、回收终稿图提醒 |
| 统一第二章、第三章或多章格式 | 不能只统一字体，要统一章节功能、标题语法、图表口径和小结方式；同级标题应像同一个体系写出来的 | 章节功能表、标题重命名建议、跨章格式规则、统一后自检清单 |
| 确认手册、模板或资料需求 | 先判断哪些资料是必需，哪些是可选，哪些可以公开检索，哪些必须由用户确认；不拿不确定材料硬写正文 | 必需资料清单、可选资料清单、缺失风险、继续工作的保守假设 |
| 生成风格迁移提示词 | 迁移前先讲清目标风格、禁止项、保留项和交付格式；不要只说“改得高级一点” | 风格画像、保留清单、禁止清单、分步提示词、自检标准 |
| 优化 GPT 提示词 | 先让 GPT 理解对象、任务、边界、输入材料和输出格式，再给具体命令；提示词里必须包含“不编造”和“需人工确认” | 背景说明、任务指令、约束条件、输出格式、检查清单 |
| 详细解读图片 | 先描述可见信息，再给结构关系，再做谨慎推断；看不清或无法确认的内容必须标注不确定 | 图像观察、结构解读、可能含义、不能确认项、后续提问或修图建议 |
| 优化绘图提示词 | 先确定图的用途、受众、期刊/论文/标书场景、输出格式和风格边界；提示词必须压制海报感和装饰化 | 绘图目标、布局说明、元素清单、风格约束、导出格式、验收清单 |
| 编写长章节或标书章节 | 章节不是材料堆砌，要有“本章任务-结构安排-关键内容-小结”的闭环；大章内先搭目录再铺正文 | 章节骨架、每节写作任务、图表安排、证据清单、章节小结 |

## 13. 逻辑严密性检查

使用本文件时，先跑一遍小型逻辑审查，避免把不同任务混在一起。

### 13.1 触发优先级

1. 若用户要求修改 Word/WPS 且涉及图片、公式、目录、题注或交叉引用，优先执行图片和对象保护规则，再处理文字和格式。
2. 若用户要求快速起稿，先建立目录级骨架和证据清单，再生成正文。
3. 若用户要求价值评估，先判断保护客体或成果类型，再讨论写法、价值和风险。
4. 若用户要求提示词，先补背景解释和边界约束，再给可复制提示词。
5. 若用户要求读图，先做可见事实描述，再做推断，不把推断写成事实。
6. 若用户要求终稿自检，先查阻塞项，再查质量项，最后查语言润色。

### 13.2 冲突处理

- “快”和“稳”冲突时，先稳住事实、图片、编号和目录，再压缩语言润色范围。
- “统一格式”和“保留图片”冲突时，保留图片优先，格式脚本避开图片段落。
- “风格迁移”和“事实不变”冲突时，事实不变优先，只迁移表达和样式。
- “专利/软著/论文价值评估”和“直接起草”冲突时，先给可写性判断，再给草稿框架。
- “读图讲解”和“绘图改造”冲突时，先读懂现有图，再提出重画方案。

### 13.3 最小闭环

任何输出至少闭合四件事：

1. 当前阶段：起稿、修订、格式治理、图片修复、价值评估、提示词生成或终稿自检。
2. 关键风险：事实、证据、图片、编号、引用、模板或输出边界。
3. 下一步动作：立即能做的一步，不停留在空泛建议。
4. 人工确认：哪些内容必须由用户、导师、模板、招标文件或原始材料确认。

## 14. 成果价值评估模板

当用户问“这个脚本/材料/方案/章节值不值得写专利、软著、论文或标书亮点”时，默认按以下结构回答：

1. 先判定对象：代码工具、上位机处理方法、设备方法、系统方案、文档模板、图件流程或管理流程。
2. 再判定保护方式：发明专利、实用新型、软件著作权、论文方法、标书亮点、内部技术规范。
3. 再判定价值等级：高、中、低，并说明依据。
4. 再判定风险：新颖性、创造性、公开风险、证据不足、过度抽象、普通自动化、格式类规则不可保护。
5. 最后给可执行方案：建议标题、主权利要求主轴或软著名称、需补材料、是否建议预审或先检索。

提示词：

```text
请评估以下材料是否适合整理为专利、软著、论文方法或标书亮点。要求：
1. 先区分材料属于代码工具、技术方案、文档模板、图件流程还是管理方法。
2. 不把普通脚本或格式规则硬包装成高价值专利。
3. 用“技术问题-技术手段-技术效果”判断是否适合专利。
4. 输出价值等级、可写方向、风险点、需补证据和建议标题。
5. 结论必须克制，涉及法律判断时提醒用户找专业代理人最终确认。
```

## 15. 需求确认模板

当材料不全但可以推进时，不要卡住；先把缺口分层。

```text
请先确认完成这个文档/章节/图件/格式任务需要哪些材料。要求：
1. 分成必需资料、可选资料、可公开检索资料、必须由用户确认资料。
2. 对每项资料说明用途和缺失后果。
3. 在资料不全时给保守推进方案，不编造缺失内容。
4. 输出一个“现在可做”和“等资料后再做”的任务清单。
```

## 16. 读图与绘图提示词模板

读图讲解：

```text
请详细解读这张图。要求：
1. 先描述图中可见元素，不做过早推断。
2. 再说明元素之间的层级、流程、因果或对比关系。
3. 把确定信息和推测信息分开。
4. 标出看不清、需要原图或需要人工确认的位置。
5. 最后给出论文/报告中可使用的图题、图注或正文解释。
```

绘图提示词：

```text
请生成适合论文/标书使用的绘图提示词。要求：
1. 明确图的用途、读者、版式比例和输出格式。
2. 列出必须出现的元素、关系、箭头、编号和标注。
3. 风格要求正式、清晰、低装饰，不要海报感、炫光、复杂背景或夸张渐变。
4. 对文字、线宽、配色、留白和缩印可读性给出约束。
5. 输出后附自检清单，检查是否信息完整、层级清楚、黑白可读、可放入 Word/WPS。
```
